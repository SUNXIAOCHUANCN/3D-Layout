# 公共编辑能力边界与迁移方案

日期：2026-11-09  
状态：边界设计，尚未迁移代码。以下“当前”来自本次工作区核对；“目标”中的目录和接口均为拟定方案。

## 1. 本次结论与范围

人工编辑保持独立插件。现有 AI 编辑插件需要修改能力调用层：把通用计算从工具实现中提取出来，调用公共能力；保留各插件的交互、工具协议、权限、任务流程和提交方式。

公共能力属于宿主提供的基础支持，第一阶段不新增“地形插件”开关，不建设动态插件市场或通用插件加载框架。插件独立，指不依赖另一个编辑插件的实现、启用状态和会话；可以依赖宿主公开的数据及编辑接口。

本轮仅整理边界、迁移路径和验收条件，不修改运行逻辑。后续先做保持行为的提取，再开发人工编辑新功能；不能把当前 AI 工具已有实现等同于人工笔刷已经完成。

本方案不改变 [LLM 插件升级设计](./LLM插件升级设计.md) 中的自主工具选择原则，也不把 CoAgent 的编排迁入普通 LLM 插件。[导入导出插件](./ThreeJS双向导入导出插件架构设计.md) 继续按自己的磁盘交换契约工作，不强制改成内存编辑插件。

## 2. 当前代码归属

| 能力 | 当前位置 | 实际边界与问题 |
|---|---|---|
| 场景类型、地形及材质数据 | `src/core/types.ts` | 已是公共数据；普通模型覆盖只有颜色、粗糙度和金属度，尚无完整材质槽体系 |
| 场景内存数据 | `src/core/store.ts` | 宿主事实数据，不应成为每个插件各自维护的副本 |
| 编辑、事务、撤销与重做 | `src/core/edit.ts` | 已共用；主要围绕单个资产 before/after，尚未覆盖环境、相机及未来资源修改 |
| 后端工作区与历史校验 | `server/workspaces.mjs` | 与前端编辑契约共同决定哪些历史能持久化，不能只改前端 |
| 人工编辑 | `src/modules/editor/` | 面板、快捷键、单选、变换及事务；当前直接使用 core 接口 |
| 参数化地形生成、采样、基础材质覆盖 | `src/modules/llm-agent/generationTools.ts` | 通用算法与 AI schema、事务、生成产物解析混在一起；写入来源固定为 agent |
| 地形雕刻、散布、批量变换、吸附 | `src/modules/llm-agent/sceneTools.ts` | 通用计算嵌在 AI 工具回调；部分吸附使用渲染对象射线，不能全部当纯计算搬走 |
| 地表权重、图层、规则所需计算与校验 | `src/modules/terrain/surface.ts` | 大部分已独立于 AI；规则执行和坐标适配仍有逻辑留在 AI 工具中 |
| 地表 AI 工具包装 | `src/modules/llm-agent/terrainSurfaceTools.ts` | 同时承担工具协议、通用操作编排和场景写入，需要拆分 |
| 地形几何、纹理与材质渲染 | `src/modules/terrain/TerrainModel.tsx`、`material.ts` | 被宿主渲染组件直接使用，实际是公共渲染支持，不是独立开关插件 |
| 地形加载校验 | `src/core/loader.ts`、`persistence.ts` | 目前反向依赖 `modules/terrain/surface`；迁移后应改为依赖公共数据校验 |
| 分区 AI 地形与材质工具 | `src/modules/partition-agent/` 下同名文件 | 有相似实现，但通过自己的 `scopedEdit.ts` 保持区域权限，不能整体替换为普通 AI 写入 |
| 普通 AI 后端任务接入 | `src/core/serverAgentTransport.ts`、`server/tasks.mjs` | 包含草稿预览、执行回执、恢复与确认提交；提取算法不能绕过这条链路 |
| CoAgent 接入 | `src/modules/coagent/adapters/editorAdapter.ts` | 已有插件读写端口和写入约束；继续使用自己的契约，按需适配公共能力 |

`src/modules/agent/`、`llm-agent/`、`partition-agent/`、`coagent/` 是不同接入方，不应笼统当作一套 AI 插件，也不应因为共享算法就自动给所有接入方开放新工具。

## 3. 目标分层与依赖方向

```text
人工编辑插件       普通 AI / LLM 插件       分区 AI 插件       CoAgent
面板、笔刷         工具、提案、日志          分区、调度         自有工作流
    │                    │                    │                 │
    └────────────── 各自接入适配器 ─────────────┴─────────────────┘
                              │
                 宿主绑定的公共编辑能力接口
                 领域计算 + 读取/写入/视口端口
                     │                   │
               受约束的编辑入口       视口查询入口
                     │                   │
               事务、历史、保存       渲染对象与射线查询
                     │                   │
                     └────── 场景渲染 ────┘
```

目标依赖规则：

1. 领域计算只依赖公共数据类型及确定性的数学工具；不导入 React、Zustand、AI 模块、文件服务或 Three.js 渲染对象。
2. 公共能力只依赖领域计算和端口定义；通过宿主装配取得读取、写入及视口服务，不自行寻找插件或全局 store。
3. 插件通过自己的适配器接入公共能力。人工插件不能导入 AI 的 `tools.ts`、工具数组、会话 store 或执行回调。
4. 宿主集成层可以引用插件入口并注入服务；领域与数据基础层不能反向导入插件。
5. Three.js 几何、材质、纹理、拾取和截图的实现归渲染/引擎适配层。插件可以控制交互辅助件，不能以直接修改渲染对象代替场景文档编辑。
6. 第一阶段不要求一次消除全部历史依赖；本次迁移涉及的地形、材质路径先满足规则，其余另行记录。

## 4. 谁负责什么

| 层/模块 | 应负责 | 不应负责 |
|---|---|---|
| 公共数据契约 | 场景、地形、材质及引用的数据表示、版本、校验 | 插件是否启用、面板状态、模型工具协议 |
| 地形领域计算 | 高度生成、采样、雕刻、权重绘制、规则与混合参数计算 | 选中对象、弹窗、申请事务、提交保存 |
| 材质领域计算 | 参数校验、覆盖合成、重置、未来材质槽和资源绑定计算 | GPU 纹理加载、AI 提案、直接修改共享 Mesh 材质 |
| 布局领域计算 | 散布位置、网格吸附、包围盒对齐、变换结果 | 访问活动相机、直接向渲染树发射射线 |
| 公共编辑能力 | 根据已授权视图读取数据，调用计算，生成并提交受约束的编辑计划，返回影响摘要 | 自行决定 AI 是否接受提案、扩大调用者权限、自动套用未请求的工具 |
| 宿主编辑运行时 | 场景身份、写者互斥、事务、历史、重做、保存及冲突处理 | 地形笔刷样式、模型选哪个工具、分区任务策略 |
| 渲染/引擎适配 | 场景数据显示、几何和 GPU 资源生命周期、表面射线与截图 | 保存一套与场景文档不一致的内容 |
| 人工编辑插件 | 面板、资源选择、快捷键、笔刷手势、参数预览；按手势请求事务 | 第二套地形算法、第二份正式场景、AI 工具调用 |
| 普通 AI / LLM 插件 | 工具白名单和 schema、结果包装、生成产物解析、请求循环、提案和日志 | 自己维护另一套高度生成及材质绘制算法 |
| 分区 AI 插件 | 区域所有权、目标区域校验、任务调度、会话数据及受限接入适配 | 用共享算法入口绕过分区校验 |
| CoAgent | 自有端口、编排、验证和运行撤销资格 | 为本次提取被迫更换工作流或自动增加地形工具 |

核心区分：共享的是“如何计算并表达一次编辑”，插件保留“为什么编辑、何时编辑、允许编辑哪里、以什么交互发起”。

## 5. 公共能力清单

### 5.1 首批提取：地形与现有材质

以下为拟定能力名称，不是已经存在的 SDK：

| 能力 | 输入与输出 | 边界 |
|---|---|---|
| `terrain.generate` | 尺寸、采样、噪声、种子 → 高度场数据 | 不自行加入场景；相同参数保持现有确定性 |
| `terrain.validate` | 高度场 → 校验结果 | 校验长度、有限数值、尺寸与当前限制 |
| `terrain.sample` | 地形、变换、查询点 → 高度/范围外结果 | 保持现有三角网格插值及坐标支持限制 |
| `terrain.sculpt` | 地形、变换、笔刷操作 → 新高度与影响范围 | 首批保持抬高/压低、压平、平滑语义；不承担鼠标采样 |
| `terrain.surface.configure` | 图层与资源配置 → 新表面数据 | 保持当前重新配置会重置绘制的语义 |
| `terrain.surface.paint` | 表面、笔刷操作 → 新权重与影响范围 | 保持归一化、擦除回基础层及当前四层上限 |
| `terrain.surface.applyRules` | 地形、规则 → 新权重 | 保持当前规则顺序、过渡和坐标口径 |
| `terrain.surface.setMaterial/setBlend/reset` | 参数 → 新表面数据 | 修改材质不隐式清空已有绘制；重置须明确模式 |
| `material.apply/reset` | 原资产覆盖、参数 → 新覆盖 | 保持实例隔离；分层地形继续拒绝普通整体覆盖 |

领域计算可返回变化摘要，但不读取全局场景、不铸造正式资产 ID、不写历史。

公共编辑能力另提供“创建地形对象”“雕刻指定地形”“修改对象材质”等入口，负责通过绑定的读取/写入端口把上述数据结果应用为场景修改。正式 ID 由宿主写入边界分配或保留现有分配策略，避免多个插件各自生成冲突 ID。

`pythonResultId` 及 Python 结果缓存属于 AI 插件。由插件先解析为标准高度场，再调用公共校验和创建；公共地形生成不依赖 Python 服务。

### 5.2 后续提取：布局与放置

- 散布、阵列、网格吸附和包围盒对齐：共享确定性的计算。
- 地形贴地：复用公共高度采样；任意模型表面贴合：调用视口表面查询端口。
- `asset.snap` 中的 Three.js 对象访问与射线查询留在引擎适配层，不跟随算法进入纯领域目录。
- `src/shared/modelBounds.ts` 已有的几何计算按依赖情况复用，不为目录统一而重写。
- 多对象编辑先生成全部变更，再按调用方现有提交模式应用；“一组命令原子提交”需由宿主明确支持，不能只靠循环调用假定成立。

### 5.3 新增人工功能的归属

人工笔刷光标、笔划插值、快捷键和面板归人工插件；笔划作用的高度/权重计算归公共领域；局部网格和纹理上传归渲染；笔划合并、撤销和数据压缩归宿主历史。

多选状态归人工工具状态；对象分组、命名、隐藏、锁定若作为可保存内容，则进入场景数据和公共编辑。灯光、环境、正式相机、完整材质槽属于后续公共数据与编辑能力，第一阶段不假装当前已有支持。

## 6. 接口与写入约束

公共能力分为“纯计算接口”和“宿主绑定的场景操作接口”。建议由宿主在装配插件时创建后者，并注入受限的读取、写入和视口端口；参数中的 `source`、`regionId` 等不能充当授权凭据。

一次场景操作需要的上下文包括：当前场景身份及会话、调用来源、操作标签、取消信号、调用方现有事务/提交模式，以及可用的读取和写入范围。身份与权限由受信任适配器绑定，不由 AI 参数或普通表单随意指定。

具体约束：

1. 通用计算返回完整结果或变更计划；计算成功不代表场景已提交。
2. 所有内容写入经过宿主编辑入口；公共领域函数不能直接 `setState` 或调用全局 `edit`。
3. 分区适配器应用计划时仍经过 `scopedEdit` 或等效检查；不能先查权限后改为无约束的核心写入。
4. 批量计划必须先完整验证；出现越权、无效目标或版本过期时，不得意外应用前半部分。现有不具备原子语义的入口须先保留并标注限制，再单独升级。
5. 异步读回结果应用前重新检查场景会话、目标状态和取消信号；切场景后的旧结果不能落到新场景。
6. 公共能力不自行开启/提交嵌套事务，也不把一次工具调用强制扩展为整轮 AI 事务。
7. 读接口提供只读数据视图或隔离副本，不暴露可被插件原地修改的正式高度/权重数组。
8. 返回值区分无变化、预览已应用、已进入本地历史、保存待确认及保存失败；不得把 `boolean=true` 或调用了 `commit()` 当成后端已持久化。
9. 错误由公共层给出稳定分类，如无效参数、场景过期、目标不存在、事务占用、越权、资源无效。AI 映射为工具结果，人工插件映射为用户提示。

初期可在现有适配器内封装这些边界，不必一次新增完整插件 SDK。`core/commands.ts` 继续作为兼容入口，不能再成为第二套修改、权限或历史实现。

## 7. 各插件具体怎么改

### 7.1 人工编辑

- 在自己的插件内新增地形创建、笔刷和材质面板。
- 适配器绑定人工来源和人工写入条件，调用公共能力。
- 一次落笔申请一个事务，抬笔提交，Esc/指针取消/卸载按明确规则回滚；取消后恢复相机操作与鼠标捕获。
- 工具状态属于插件；关闭插件释放监听、光标和预览，不删除已提交内容。

### 7.2 普通 AI 与 LLM 实验插件

- 已有地形、材质工具回调改成：解析工具参数 → 调用公共能力 → 包装兼容结果。
- 保留工具名、参数 schema、默认值、单位、返回字段、限制和已知边界；公共能力扩展不自动扩展工具白名单。
- 保留权限模式、提案接受/拒绝、取消、日志和后端任务重连。现有 `agent` 未提供的地形工具不因本次提取被自动加入。
- 默认后端任务通过 `ServerAgentTransport` 执行浏览器工具并管理草稿/回执，确认提交由后端任务链路完成；共享能力不能额外提交一次正式历史。
- 浏览器传输模式继续使用原有任务事务；两种执行路径均须验证。

### 7.3 分区 AI

- 提取与普通 LLM 重复的计算；保留区域权限和立即写入语义。
- 当前 `createScope()` 返回的是区域权限句柄，其 `commit/rollback` 是空操作，并非核心事务。不能因为类型为 `TxHandle` 就把它传给普通事务实现。
- 共享能力使用其绑定的受限写入端口；原有 owners 更新、取消检查及 changed 通知继续执行。
- 多分区任务不能在仅支持一个 `openTx` 的核心上各自开启全局事务。首轮保持原有写入粒度，并把未来批量原子性作为独立改造。
- 区域所有权只检查资产归属，不等同于将同一地形的笔刷限制在区域内。跨区地形局部授权若需新增，另行定义空间掩码与数据写入规则。

### 7.4 CoAgent、历史与导入导出

- CoAgent 保留现有读写端口、写入门面、指纹、运行与撤销资格；没有新增地形调用需求时不改工具集。
- 依赖核心历史结构的适配器和持久化路径，在历史格式升级时一起适配。
- 历史侧栏仍是公共历史的查看者，不承担每种插件的撤销实现。
- 独立导入导出继续读写约定的磁盘格式；公共数据或资源格式升级时补兼容，不让它读宿主内部 store。新场景导入/删除的文件事务不冒充当前场景的一条 Ctrl+Z 记录。

## 8. 历史与持久化的共同边界

“所有编辑进入历史”指所有改变场景内容和输出的操作：资产、地形、材质、分组、环境、灯光及正式相机。选择、笔刷半径、面板折叠和临时浏览视角默认属于工具/观察状态；导入创建工程、删除场景等跨文档操作需独立生命周期方案。

公共能力提供语义标签和影响对象，宿主统一记录 before/after 或差量。人工笔划、滑块拖动以及明确的批量编辑各对应一个事务；无变化不留记录，失败/取消回到明确边界，后续新编辑按现有线性历史规则清除重做分支。

本次核对发现的现有限制，不能当成已解决：

- 前端 `EditCommand` 包含 `update_asset`，后端 `validateWorkspace` 当前仅接受 `set_transform/add_asset/remove_asset`。事务压缩会把既有对象修改归为 `set_transform`，掩盖语义差异；无事务的 `updateAsset` 路径存在被后端拒绝的契约风险。正式改动时须覆盖测试并共同修正，本文不宣称已经复现保存失败。
- 当前期刊保存完整资产 before/after。事务提交虽会按资产合并，但操作期间仍可能积累多份大数组；仅做“一笔一条显示记录”不足以解决内存问题。
- 现有数据和历史以资产为目标，尚不能表达环境、正式相机及未来共享材质资源的全部修改。
- 后端任务提交也会根据资产差异构建历史；只改浏览器 `edit.ts` 不足以支持新历史类型。

迁移策略：算法提取阶段先保持既有场景格式；笔刷和新数据上线前，再统一设计版本化历史、后端校验/回放、持久化恢复及旧记录兼容。地形采用局部差量与适当检查点，期间合并同一区域变更；具体压缩格式通过实际笔划内存与保存量验证后确定。

贴图/材质资源注册由宿主管理。AI 的临时结果缓存不能成为正式场景资源来源的唯一凭据；撤销/重做仍引用的资源不得随插件关闭或替换操作立即删除。资源清理需考虑当前场景、历史与检查点引用，不能只看当前画面。

## 9. 目标目录建议

```text
src/
  core/
    types.ts                 # 保留现有公共类型，按需要逐步拆分
    edit.ts                  # 唯一正式编辑与历史入口
    capabilities/            # 拟新增：公共能力编排、端口与宿主绑定
  domain/                    # 拟新增：纯数据计算，不依赖插件和渲染
    terrain/                 # 高度生成、采样、雕刻、地表计算与校验
    materials/               # 参数校验、实例覆盖和未来资源绑定
    layout/                  # 后续提取：散布、对齐等计算
  components/
    terrain/                 # 拟迁入：TerrainModel、GPU 材质实现
  modules/
    editor/                  # 人工交互 + 自己的能力适配器
    agent/                   # 保留原插件及工具边界
    llm-agent/               # AI 工具包装 + 自己的能力适配器
    partition-agent/         # 区域权限 + 受限能力适配器
    coagent/                 # 保留自有契约和工作流
    history/                 # 公共历史展示
```

这不是立即执行的文件搬迁清单。先提取清晰的小模块，必要时给旧路径保留临时兼容导出；兼容导出只能从旧模块指向新公共模块，公共模块不能反向依赖旧插件。完成调用方迁移后再删除旧实现，避免长期维护两份算法。

## 10. 实施顺序与阶段完成条件

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| A：建立行为基线 | 记录现有工具输入输出、生成种子、坐标与材质边界；覆盖普通事务、分区写入、后端任务路径 | 能区分提取造成的回归与原有问题；历史契约风险有明确复现或排除结论 |
| B：提取纯算法 | 高度生成/采样/雕刻、现有地表计算与校验、基础材质覆盖；渲染实现按职责迁移 | 公共算法不导入 AI/UI/store；相同输入与旧实现结果一致 |
| C：迁移插件调用 | LLM 工具改用公共能力；分区工具通过受限端口复用；保留兼容外观 | 原有工具行为及提案/分区权限不变；无额外历史提交；普通人工变换仍工作 |
| D：完善写入及历史契约 | 对齐前后端操作类型；补新目标类型、版本与旧历史恢复；建立笔划增量记录 | 本地撤销、后端保存和刷新恢复一致；数据量受控；失败不产生半次编辑 |
| E：开发人工工具 | 地形创建、雕刻、地表绘制、材质面板和交互生命周期 | AI 全部关闭时可完整人工制作；一笔一条历史；取消与卸载可恢复 |
| F：按需扩展 | 布局计算、多选、灯光/环境/相机、资源包兼容 | 新能力沿用同一数据和历史入口，不反向依赖某个编辑插件 |

若 B/C 迁移遇到历史持久化阻塞，先完成 D 中相关的契约修正再切换对应调用；不能为了严格阶段顺序让已迁移能力失去保存能力。

## 11. 验收清单

1. 关闭所有 AI 插件，人工插件能够创建、雕刻、绘制、撤销、重做和保存地形。
2. 关闭人工插件，已有 AI 工具继续工作；不自动扩充工具、修改提示策略或改变提案粒度。
3. AI 创建的地形可人工编辑，人工创建的地形可被有权限的 AI 工具编辑；无需转换成另一种地形类型。
4. 两类插件都关闭时，已提交地形及材质仍可加载和渲染。
5. 固定种子的生成结果、采样插值、笔刷衰减、世界/局部坐标和权重归一化保持一致。
6. 分区 AI 越权写入仍被拒绝，owners/取消/切场景检查仍生效；公共能力不提供旁路。
7. 普通 AI 提案拒绝和任务重连不重复编辑或重复生成历史，已提交批次保持现有语义。
8. 人工一笔对应一条历史；Esc、指针取消、插件卸载及目标失效可按约定结束事务，不留下占用锁。
9. 地形/材质历史经过后端校验，刷新及服务重启后能继续撤销和重做；旧场景和历史仍可读取。
10. 新增完整材质与环境/相机能力时，前端、后端、审查差异、历史面板和资源导出一起验证，不能只验证视口效果。
11. 性能验收使用当前支持上限的高度场/权重图和连续笔划，记录帧耗时、临时与历史内存、保存体积；门槛在实际基线后确定，不凭空许诺帧率。
12. 静态依赖检查确认人工编辑不导入其他编辑插件、领域计算不导入 store/React/渲染，涉及的 core 校验不再反向依赖原 `modules/terrain` 路径。

验证优先沿用现有地形单测/浏览器探针、后端工作区及任务测试、分区和 CoAgent 检查；只为提取后的关键行为与边界补必要测试，不为单纯移动文件重复建设测试体系。

## 12. 本次已经确定的设计决定

- 采用“独立编辑插件 + 宿主公共能力”，当前不新增可卸载地形能力插件。
- 现有 AI 插件需要调整相关工具的内部实现，保留外部工具契约与工作流。
- 地形/材质算法只维护一份；鼠标笔刷与 AI 工具分别开发自己的交互包装。
- 地形和材质的正式数据及渲染独立于编辑插件开关。
- 区域权限、提案与确认提交不随算法提取丢失，也不合并成一套通用 AI 工作流。
- 历史与持久化归宿主，须前后端一起升级；本设计文档不代表这些改造已经完成。
