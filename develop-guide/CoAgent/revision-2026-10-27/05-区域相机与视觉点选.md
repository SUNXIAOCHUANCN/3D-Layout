# P2：区域独立相机、最新图片与截图点选

## 1. 产品行为与范围

采用方案 B：先聚焦目标，再连续环绕、俯仰、缩放和平移。Agent 可以自由观察，但不需要自己计算世界坐标相机位置。

首版工具默认“调整并截图”，返回相机实际状态、图片和 observationId。底层仍保留相机参数计算与 capture 的分离，供固定验收复拍和测试使用。

已有 `camera.focus/set/capture` 的工具链不能突然失效。可新增 `camera.overview/inspect/adjust/restore`，或为旧工具增加明确模式；在注册 schema 与提示中只暴露一种推荐用法，避免同义工具过多。

截图点选属于定位，不是新的写入方式。已知 ID 时直接使用 ID；未知时点选得到 ID，再走 edit 工具。首版不做屏幕拖拽与 gizmo。

## 2. 服务与状态归属

建议 `services/regionCamera.ts` 负责纯相机计算，`runtime/regionViews.ts` 持有本 run 每个区域状态：

```ts
type RegionViewState = {
  regionId: string
  camera: CameraSnapshot
  target: [number, number, number]
  focusedObjectIds: string[]
  viewVersion: number
  latestObservationId: string | null
}
```

由 tool call 的 runId/regionId 确定归属，不允许模型传另一区域 ID 修改其他 Agent 相机。保存视角带 run/region 身份，restore 只能恢复有权限的视角。

每区只有工作相机状态，底层渲染继续共享真实场景。禁止复制场景给每个 Agent，禁止借用户主视口相机完成捕获。

## 3. 建议工具契约

```ts
camera.overview({})
camera.inspect({ objectIds: string[], framing?: 'tight' | 'context' })
camera.adjust({
  azimuthDeltaDeg?: number,
  elevationDeg?: number,
  zoomFactor?: number,
  pan?: { right: number, up: number } // 当前画面跨度的比例
})
camera.restore({ viewId: string })
scene.pick({ observationId: string, u: number, v: number })
```

`zoomFactor < 1` 表示拉近，>1 表示拉远；pan 正右、正上，均按画面坐标定义，避免 world Z 正负混淆。参数必须有限，工具说明用同一含义。

每次调整可合并环绕、俯仰、缩放，避免三个模型回合才完成一次观察。返回完整 CameraSnapshot 和视角 ID，不只回显请求参数。

`inspect` 多对象取包围盒并设置有限余量；默认 context。允许聚焦指定地点可后续增加，首版无对象时使用区域总览与 pan 即可。

## 4. 相机计算规则

- 总览依据区域多边形，不能按本区海面等超大对象的并集取景。
- 聚焦用 `modelWorldBounds` 等统一包围盒计算，兼容负缩放、旋转和标准化资产；缺元数据时应明确采用保守估计。
- 世界 +Y 向上。透视环绕可用 `offset = d * [cos(e)*sin(a), sin(e), cos(e)*cos(a)]`；将 a=0 明确约定为从 +Z 方向看向中心，正角转向 +X。测试依此验证。
- 默认透视 FOV 固定，通过距离缩放；正交模式修改可见范围，不把移动高度当正交 zoom。
- 俯视正交切换到透视时要保留中心和大致取景尺度，避免突然跳远。
- 俯仰避免 lookAt 与 up 平行产生奇异。建议工作透视允许接近水平到高位斜视，严格 90° 顶视走 overview；具体限值集中配置并测试。
- 距离下限和 near/far 根据目标尺度计算，不固定为适用于所有场景的米数。
- 相机可以在区域外；视角位置不授予区域外对象写权限。
- focusedObject 被删除时返回可恢复错误，或显式退回总览并说明原因，不能继续对旧包围盒声称已聚焦。
- 参数夹取必须在结果中报告实际值及 warnings；非法参数拒绝，不生成 NaN 相机。

## 5. 截图与渲染一致性

现有 `rendering/capture.ts` 的 `cameraFromSnapshot` 已能构建独立相机，复用该入口。新增取景不通过 `engine.focusAsset()` 改用户相机。

每个 Observation 保存：相机参数、实际输出宽高、sceneRevision、partitionVersion、目标 ID、可用指纹、run/task/region、时间和图片 ID。

建议工作截图默认 640×480、局部可用 960×720，设配置上限。这是起始配置，不是性能保证；用实际浏览器结果调整。固定前后对比采用一致尺寸。

共享渲染与场景修改需要可解释的时序：

1. 资产就绪等待尽量在场景临界区外完成。
2. 在队列内确认状态、更新矩阵、捕获像素并记录对应 revision。
3. 编码可在队列外进行，但必须使用已经复制并独立拥有的像素，不能让下一次 capture 覆盖同一 render target 内容。
4. 拾取与对象修改同样按顺序处理。
5. 不允许持有 runScene 队列再递归调用会排入同一队列的 capture，避免死锁。明确哪一层拥有调度。
6. 任何异常通过 finally 恢复 GPU 状态；用户相机、controls、selection 不变。

只修改图片尺寸不能保证效果；必须检查场景中目标实际占屏大小。

## 6. 模型图片上下文

替换 `executor.ts` 的前两张图上限，建立有界最新证据窗口：

- 保留任务基线（需要前后比较时）；
- 优先保留最新观察；
- 允许保留一组同视角前后图；
- 旧消息图片移除后保留文字元数据和 observationId，不破坏 tool call/result 配对。

不能只让 imagesForToolResult 无限返回图片，否则 transcript 会累积所有图片。应在 modelLoop 构造每轮请求时重建/裁剪图片窗口，用稳定证据 ID 标识图片；文本与图片顺序必须一致。

建议默认最多 4 张，根据模型能力配置。judge 的固定 before/after 加最多 2 张相关局部图；只有真正附上的图片才标记为“已提供视觉证据”。可引用 ID 与实际附图列表分别校验，不能声称看过只列了 ID 的图。

额外图须与当前相关对象状态匹配；对象被修改后旧局部图不能作为最终状态图。新增对象优先标注，环境对象再补到标注预算。

## 7. 视觉点选实现

现有 `src/core/engine.ts::pickNormalized` 使用主视口 camera，不能直接用于 Agent 离屏图。抽取渲染侧拾取函数，参数为 scene、Observation 相机和尺寸、u/v。

处理顺序：

1. 检查 observationId 属于当前 run、当前区域允许访问的观察。
2. 检查 u/v 为 [0,1] 的有限数。
3. 在场景队列中核对 observation.sceneRevision 与当前 revision；首版不一致返回 stale_observation 并提示复拍。
4. 使用 capture 同一个 cameraFromSnapshot，更新 scene/camera 世界矩阵。
5. 图像坐标转 NDC：x=2u-1，y=1-2v。
6. Raycaster 拾取，排除编辑辅助件，检查物体及祖先可见性，沿父链寻找 assetId。
7. 返回最前面的有效命中，映射当前资产、指纹、权限、命中点。
8. 可返回带轮廓/局部图的反馈；不要改变全局 selectedAssetId。

响应建议：

```ts
{
  observationId,
  sceneRevision,
  hit: null | {
    objectId, point, distance,
    ref, name, transform, fingerprint,
    regionId, writableByTask, restrictionReason
  },
  feedbackObservationId?: string
}
```

空命中是正常结果，不自动吸附最近物体。命中只读对象仍可返回详情，但写入权限为 false。不得只对可写对象 raycast 后“穿过”前方只读对象。

透明材质/alphaTest 与射线表面不完全一致，第一版用资产样本验证；无法保证的情况返回限制提示并建议换角度，不声称获得逐像素可见性。后续可引入截图时保存的 ID buffer 解决精确可见性和旧图映射，但不能把后续能力写成首版已有。

## 8. 预算与验收

观察工具计入任务预算；可增加单任务截图上限，达到时返回明确预算耗尽。预算不足导致无法确认，不能自动当 pass。

验收：调整后模型收到的是最新图；两区交替 capture/pick 不串相机；俯视与透视点选命中一致；旧图拾取被拒；选择不改变用户 UI；复拍参数与画幅一致；负缩放模型和遮挡样本可正确处理。
