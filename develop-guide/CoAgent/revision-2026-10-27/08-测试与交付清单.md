# 测试矩阵与最终交付

测试用例应验证用户行为和跨组件不变量，不仅检查新增字段或复制实现逻辑。首次实施先运行相关原有测试，记录已有失败，避免把基线问题误归因本修订。

## 1. P0：碰撞语义

| ID | 场景 | 预期 |
| --- | --- | --- |
| G01 | 用户只说添加几栋房屋 | 新计划不默认含 no_collision，也不绕到 visual 要求全局零相交 |
| G02 | 用户明确要求所有对象不得相交 | 合法依据允许硬约束；伪造/不相关引用被拒绝 |
| G03 | 原场景静态对象互相碰撞，新增对象正常 | 动态检查不包含静态×静态，不受旧碰撞影响 |
| G04 | 动态与山体相交 | 诊断准确报告；是否导致任务 fail 取决于显式判据 |
| G05 | 候选超预算 | 返回 unknown/覆盖不足，不伪报 clear |

## 2. P1：状态与修复

| ID | 场景 | 预期 |
| --- | --- | --- |
| S01 | 新增一个对象后立即 list_region | 返回真实 ID，数量+1，revision准确 |
| S02 | 删除后查询与验收 | 对象消失，数量一致，审计保留删除记录 |
| S03 | 创建两栋、视觉失败进入修复 | executionState包含两栋最新状态，remaining=0 |
| S04 | 修复再次 add 第三栋 | 程序拒绝，无场景副作用 |
| S05 | 调整第一栋 | 允许并更新当前指纹，不增加数量 |
| S06 | 删除一栋再创建 | 释放一个名额，最终存活两栋 |
| S07 | 两个新增同时争最后名额 | 只一个成功，数量不超限 |
| S08 | 同幂等键重试成功 add | 返回原 ID，不重复计数；参数不同拒绝 |
| S09 | 旧指纹真正不同状态写入 | stale_object；重新读取后成功 |
| S10 | 排队中取消、随后作业开始 | 队列内检查拒绝迟到写入 |
| S11 | 同区第二任务开始 | 看得到前任务对象，但自己成果为空、证据不串 |
| S12 | 第二任务失败 | 结果保留第一任务记录，后续任务有跳过原因 |
| S13 | 点到同区但非任务目标 | 不能因此获得修改权限 |
| S14 | 回滚或新 run | 不残留旧临时 ledger、token、名额 |

涉及 tests/unit/tools、validation、schemas、planValidation 和 tests/integration/w05-flow、w08-final、runController；新增纯 runState 测试及真实写门面集成测试。

| ID | 场景 | 预期 |

## 4. P3：保留与撤销

| ID | 场景 | 预期 |
| --- | --- | --- |
| R01 | 部分任务验收失败 | 有效修改保留，判据仍fail/uncertain |
| R02 | 保留后立即撤销 | 一次恢复整轮，早前历史不变 |
| R03 | 保留后用户又编辑 | 快捷撤销不误撤最新用户操作 |
| R04 | 新场景/同场景重新加载 | 旧historyRef不可用 |
| R05 | 无实际写入 | 无本轮撤销入口，不借用上一条事务 |
| R06 | 保存失败 | 场景保留，显示未保存，可重试 |
| R07 | commit no-op / rollback失败 | 不谎报提交或回滚成功，进入准确异常状态 |
| R08 | 运行正常终态后迟到响应 | 不能继续写入 |
| R09 | 原用户取消、插件卸载 | 首版仍准确撤销并释放锁 |
| R10 | 结果已保留后新任务 | 不被旧open transaction或busy卡住 |

使用真实 core transaction 集成测试验证历史，不能只mock undo返回true。

## 5. P4：持久化

| ID | 场景 | 预期 |
| --- | --- | --- |
| P01 | 保存、销毁runtime、重新加载 | 区域ID/边界/人工归属一致，不调用模型 |
| P02 | 无文件 | 正常未分区状态 |
| P03 | 损坏/未知格式/错误sceneId | 不启用、不覆盖，显示原因 |
| P04 | 删除、新增、跨区移动对象 | 成员核对正确，歧义不授写权限 |
| P05 | A读取慢，先切B | A响应不能覆盖B |
| P06 | 模块晚启用/StrictMode重挂 | 恢复一次有效状态，无重复保存循环 |
| P07 | scene保存成功、partition失败 | 显示部分保存，重试可用 |
| P08 | 连续修改后旧保存响应返回 | 不清除新dirty，不回退文件内容 |
| P09 | 场景未保存，单独保存分区 | 不隐式保存场景；指纹不匹配时核对 |
| P10 | Agent撤销后保存再重开 | 不恢复已删除的幽灵对象 |
| P11 | 静态托管无写服务 | 显示状态，可手动导出导入，不反复自动下载 |
| P12 | 路径越界、过大/非法JSON、多窗口旧版本覆盖 | 服务拒绝并保留旧文件 |

用临时场景目录测试IO，不覆盖用户真实场景数据。后续浏览器复测使用明确标识的副本。

## 6. 原请求端到端复现

使用 tri-biome 的测试副本，输入“在中央白色雪原添加几栋房屋”：

1. 恢复保存分区，确认成员和人工归属。
2. 规划形成具体数量；不添加未经用户要求的零碰撞和精确净距。
3. 任务新增后实时查询正确。
4. 自由观察并点选一个新增房屋，获得真实 ID。
5. 注入可控的视觉未通过结果触发修复，确认调整原对象而非重复新增。
6. 让最终判定仍 uncertain，确认结果保留且报告准确。
7. 立即撤销，确认整轮新增/修改完全恢复；再测试追加用户编辑时不会误撤。
8. 保存分区、重开副本，确认恢复与当前场景一致。

可控 fake judge 证明流程，真实模型运行验证实际图片与工具调用。两类证据分开记录。真实模型没有稳定通过不等于程序必错，但不能将 fake 通过宣称为真实布局效果通过。

## 7. 命令与验证顺序

工作目录为仓库 `src`，包管理器以当前安装环境及锁文件为准。当前 package scripts 已提供：

```powershell
pnpm test:coagent
pnpm build
```

先跑对应 unit/integration 子集，再跑完整 coagent 套件和构建；浏览器脚本见 src/package.json 中 `test:coagent-browser*` 与 probe 构建配置，先检查其服务端口、场景依赖和启动要求，不假设可直接在任意环境运行。新增相机/点选 browser suite 应明确列出启动方式与退出码。

本交接文档编写阶段不运行应用测试；这些是实施后的必做验证，不是已经通过的结果。
