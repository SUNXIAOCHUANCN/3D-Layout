# P4：不改变 Agent 架构的分区长期存储

## 1. 接入方式

推荐在 `scenes/<sceneId>/coagent/partition.json` 保存配套文件。保留核心 SceneDocument 格式，恢复后仍通过现有 runtime.setPartition/partitionProvider 输出 PartitionSnapshot。

新增 `services/partitionPersistence.ts`（文件契约、校验、核对）和 IO adapter（读写服务、下载导入）。runtime/createRuntime 与模块装配负责监听生命周期，不让 planner 或 regionGraph 直接读磁盘。

当前 `partitionOverride` 是内存状态，`commitPartition()` 是统一变更点；可扩展来源标志 `restore/generated/manual/reconciled` 防止恢复触发保存循环。

## 2. 文件格式

建议首版 schemaVersion=1，示例：

```json
{
  "schemaVersion": 1,
  "sceneId": "tri-biome",
  "partitionVersion": 2,
  "savedAt": "2026-10-27T00:00:00.000Z",
  "sceneFingerprint": "sha256:...",
  "regions": [
    {
      "id": "region-snow",
      "name": "中央雪原",
      "polygonXZ": [[-30,-90],[30,-90],[30,0],[-30,0]]
    }
  ],
  "assignments": [
    {
      "objectId": "snow-house-1",
      "regionId": "region-snow",
      "source": "manual",
      "ref": "models/snowytownhouse1"
    }
  ],
  "readonlyAssignments": [],
  "unresolvedObjectIds": []
}
```

示例仅表示字段，不是实际场景边界，不能把示例多边形写入真实场景。

- schemaVersion 表示格式版本；partitionVersion 表示区域定义/显式归属改变；普通位置变化不必递增分区定义版本。
- 保存多边形的世界米制 XZ，不保存仅能依赖旧相机解释的 UV 提案。
- 保存稳定区域 ID；恢复时不得重新按名称生成 ID。
- assignments 来源为 auto/manual/agent；只读赋值也保存来源，避免把人工只读误判为可写。
- 对象 ID 与 ref 可用于发现明显身份变化；相同 ID/ref 也不能绝对证明是原对象，内容变化需核对，不要声称实现了全局资产 UUID。
- 不保存 objectCount；它在恢复时计算。
- 不保存 token、runState、当前模型对话、临时证据图片、尚未提交的编辑事务。
- 相机默认值可由区域边界生成，工作相机历史首版不持久化；后续可单独版本化加入。

## 3. 内容指纹

使用与布局相关的规范化序列化内容计算：资产按 ID 排序，包含 ref、transform、visible，以及单位/up约定；默认 scale 等缺省值先规范化。标明指纹算法版本。名称等非空间属性是否纳入需固定并测试，不因 JSON 属性顺序变化导致不同摘要。

不要使用运行期 sceneRevision，也不要只用 meta.version。当前 saveScene 的版本号只在输出文件里递增，不能作为可靠唯一内容身份。

输入单位或坐标轴不兼容、场景 ID 不匹配属于无法直接恢复，不靠重新计算摘要掩盖差异。

## 4. 加载恢复

```text
模块首次挂载或 scene:changed
→ 获取 sceneId + sceneSessionId + loadGeneration
→ 禁止使用旧场景分区，清旧报告
→ 读取配套文件（无文件是正常情况）
→ 校验 schema/sceneId/区域/归属
→ 用当前快照核对
→ 再确认 generation 与场景仍匹配
→ setPartition(可用快照, source=restore)
→ 显示恢复状态
```

必须覆盖“模块在场景已经加载后才启用”，不能只监听未来 scene:changed。StrictMode 重挂载不重复写文件；dispose 取消请求并移除监听。

404：无保存分区；损坏或未知版本：显示不可恢复、保留文件；网络失败：显示读取失败，不等同从未生成。不应遇到任何读取失败就自动调用收费模型重新划区。

恢复期间 start 应等待恢复完成或明确返回 initializing；不能让用户在旧场景分区尚未清理时开始新运行。

## 5. 与当前对象核对

复用 P1 的归属服务和现有分区几何校验，不再另写宽松的成员算法。

| 情形 | 策略 |
| --- | --- |
| 指纹一致 | 校验后直接恢复 |
| 对象已删除 | 从运行快照排除；记录缺失项，不制造幽灵对象 |
| 对象仍存在且归属合理 | 保留原区域和来源 |
| 新对象有有效 Agent 创建归属 | 沿用创建区域并校验 |
| 新对象无归属 | 按现有锚点规则分配；唯一命中才自动确定 |
| 多重命中/未命中/跨区冲突 | 加入 unresolved；只读或从可写目标排除 |
| 人工覆盖与位置不一致 | 保留覆盖来源并报告，不静默改写为 auto |
| ID相同但ref改变等身份变化 | 标记重新核对，不能盲用旧人工归属 |
| 整体重构、单位变化 | 不自动变换旧边界，提示重新确认/划区 |

人工覆盖不豁免执行期 stay_in_region；如果边界与人工归属冲突导致不可编辑，应明确显示待处理，而不是放宽写边界。

移除对象后的旧记录可作为有限恢复信息保留，撤销重现对象时重新核对身份；运行快照绝不包含不存在对象。首版若只保存存活归属，应说明跨重启再导入同 ID 不保证恢复旧人工覆盖。

原 PartitionReport 包含模型 proposal。恢复文件时不能编造一次模型生成记录。可增加来源与恢复核对报告类型，UI 根据 source 展示不同信息。

## 6. 保存触发和一致性

触发：生成分区、人工修改、显式重新划区、已保留的 Agent 修改保存成功、用户撤销后保存成功。普通相机调整不触发。

生成与人工修改递增必要的 partitionVersion，更新 region.partitionVersion；保存本身不增加定义版本。当前 applyPartitionFix 未递增版本的行为需修正。

正常场景保存链：

```text
捕获准备保存的场景文档及内容指纹
→ 保存 scene.json
→ 用同一场景内容对应的归属构造 partition.json
→ 保存分区
→ 更新两项保存状态
```

不能收到 scene:saved 事件后随意读取已经变化的场景，并假定它就是刚保存的内容。建议保存结果/事件增加保存时内容指纹或 immutable snapshot 标识；或 adapter 封装一份一致快照进行两项保存。这个 IO 扩展不改变 Agent 工作流架构。

分区单独修改时不调用 saveScene 隐式保存用户未保存的对象编辑。可保存带当前内容指纹的分区并标为“关联场景尚未保存”；下次加载若磁盘场景不匹配，必须核对，不能视为 ready exact。

配套文件采用临时写入后替换，清理失败临时文件；限制场景 ID、文件大小和合法 schema，沿用路径边界检查。单文件原子替换不等于跨文件原子事务：scene 保存成功但 partition 失败时，显示部分保存并保留重试数据。

同一 sceneId 保存请求串行；保存成功只有当响应对应当前 dirtyGeneration 才清 dirty。旧请求不能把新修改标记为已保存，旧 scene 的响应不能更新新 scene 的面板。

多窗口冲突首版至少避免静默覆盖：使用已加载文件摘要/版本作为 expected 条件，冲突时返回冲突状态，不自动合并。若暂不实现跨进程强一致，应明确限制，不能声称完备的多人协同。

## 7. IO 接入和降级

建议读路径沿用静态场景资源 `/scenes/<id>/coagent/partition.json`，写接口可为 `/api/scene/<id>/coagent/partition`。具体命名按 Vite middleware 路由组织，确保 dev/preview 均注册；写入路径固定，客户端不得自定义任意文件路径。

现有场景保存服务在静态托管不可用，因此分区支持显式导出/导入。自动保存失败只显示状态，不在每次后台变更时反复弹下载。用户触发导出才下载，导入仍经过同一校验和核对。

复制整个场景目录可携带分区。只导出 scene.json 不包含分区，UI/文档需明确；首版不承诺整包导出。复制为新 sceneId 时需显式调整并校验场景身份，不能简单按相同名字匹配分区。

浏览器存储可作缓存或失败恢复，但磁盘文件是长期主存储；缓存不能无提示覆盖新磁盘版本。

## 8. UI 状态与完成标准

建议独立 PartitionPersistenceState：loading、absent、ready、needs_review、dirty、save_failed、load_failed；读写状态可拆字段，避免一个枚举同时承担所有组合。

面板显示来源、分区版本、待核对数量与保存状态。无文件不是错误；无法核对的目标不能获得可写权限。

完成标准：重启恢复无需模型；人工归属保留；场景切换不串数据；新增/删除/撤销后成员正确；损坏文件不被自动覆盖；网络失败可重试；运行中的冻结分区不被恢复/保存影响。
