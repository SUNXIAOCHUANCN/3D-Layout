# 人工盲评表（对应论文 A.4）

机器判分只覆盖 `asset_level_edit_precise` 一类；模糊编辑、场景批评、distractor、建造任务都得人看。
这张表是论文 A.4 的盲评流程的简化版，用于**同一个人评多组模型/提示词**时保持口径一致。

论文的做法：全局打乱 → 匿名 id → 每样本只看 query + 初始 5 图 + 最终 5 图 + 模型回复 + 碰撞结果。
本项目照抄可执行的部分：**打乱顺序、隐去模型名、初始/最终各一张截图**。

---

## 1. 每个样本看什么

| 材料 | 本项目从哪来 |
|---|---|
| 用户指令 | `cases.jsonl` 的 `instruction` |
| 初始场景截图 | 跑之前的 `viewport.screenshot` |
| 最终场景截图 | 跑之后同机位截图（**机位必须一致**，否则判不了位移） |
| 模型最终回复 | 聊天面板最后一段 |
| 工具调用记录 | 面板的工具行（判"说了没做"用） |
| 自动判分结果（可选参考） | `score_cases.py` 的输出 |

---

## 2. 五项判断（照论文 A.4 原样）

| # | 维度 | 取值 | 判据 | 对应 judge |
|---|---|---|---|---|
| 1 | **意图达成** Intent | 0/1 | 最终场景是否满足指令；满足=1 | P2 / P4（H3_pass） |
| 2 | **生态合理性** Ecological | 0/1 | 有没有客观违反生态/常识的摆放 | P1 / P3（H2） |
| 3 | **物理可行性** Physical | 0/1 | 截图里可见的穿模、悬空、尺度崩坏 | P1 / P3（H1）+ 人眼补碰撞 |
| 4 | **事实幻觉** Hallucination | 0/1（**反向**：有幻觉=1） | 回复声称的改动是否真的发生 | P2 / P4（VR 里的 edit hallucination） |
| 5 | **回复智能** Intelligence | 1–5 | 面对模糊/不可行请求是否澄清得体；5=澄清得很好，1=答非所问 | P4（H3-Response） |

**Pass@1（人评）** = 前三项都通过（=1）**且**第 4 项无幻觉（=0）。第 5 项只做参考，不计入通过。

填写约定：

- 拿不准就填 **0**（论文的口径：宁可严，判官分本来就会偏高）。
- 备注只写**具体问题**，不写"感觉不好"：写"雪村 3 号木屋被挪了 2 m（未要求）""灯柱埋进地面"。
- 一条样本出多个问题时，按**最严重的那条**判该维度。

## 4. 汇总

```
自动判分（C 档）：  pass / total = ____  （score_cases.py 直接给）
人工判分（A 档）：  pass / total = ____
分维度通过率：      意图 ____%  生态 ____%  物理 ____%  幻觉率 ____%  智能均值 ____
```

**跨模型比较只比同一批题**。A 档和 C 档的绝对分不可比（C 档有 GT、A 档靠人判），
要分开报，别混成一个 Pass@1。

## 5. 想更省力：让判官先过一遍

把 [`../prompts/20-judge-inputs.md`](../prompts/20-judge-inputs.md) 的模板拼好，
用 P1/P2 各判一次，再把判官分 ≥4 的样本抽 20% 人工复核。
论文自己也是这么校准的（p.8：生态 κ=0.54、意图 κ=0.53、case 级一致率 83.4%），
所以**判官与人工不一致是预期内的**，别为了对齐去改判官提示词。
