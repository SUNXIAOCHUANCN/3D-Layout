# 场景分区 Agent

独立插件，目录为 `modules/partition-agent`。基于 LLM Agent 实验插件的工具与多协议模型客户端建立，不改动 `modules/llm-agent`。模型档案与其他 Agent 共用，场景会话、运行状态、截图记录及 Python 结果引用独立管理。

## 使用

1. 启动或重启 3D-Layout 开发／预览服务，打开侧栏“场景分区 Agent”。该插件默认关闭，与两个单 Agent 插件互斥启用。
2. 在“模型设置”中配置支持看图的模型，并开启“截图回传给模型”。分区、总 Agent 和 SubAgent 使用此模型配置。
3. 点击“拍摄并分区”，或直接发送任务触发首次分区。
4. 观察分区逐轮预览、各区 SubAgent 的执行状态与总 Agent 汇报。Enter 发送，Shift+Enter 换行。

插件已经内置迁移自 Map2Area 的“LLM分区”工作流，运行时不读取 Map2Area 项目、数据库、模型配置、服务或文件。也不需要启动 Map2Area。原来的工作流列表、服务代理与运行轮询已移除。

内置流程：正交鸟瞰截图 → 图像压缩适配 → LLM 看图绘制 → 校验并渲染 → 将原图与结果拼成对照图 → LLM 检查／局部修订 → 通用边界平滑 → 原始与平滑结果预览 → 世界坐标分区与对象归属。

鸟瞰截图通过 HDR 中间缓冲与视口一致的色调映射／颜色转换输出，避免高光被直接截白。分区用图临时将低粗糙度材质的粗糙度下限设为 0.65，减少海面等强反射产生的高光噪点；仅使用临时材质副本，不写入场景，不改变正常视口材质。拍摄成功或失败都会恢复渲染目标、裁剪、清屏状态、材质及编辑辅助对象。

`python/preset.json` 保存实际“LLM分区”工作流第 15 版的配置快照，包括用户自定义提示词、16 轮调用上限、3600 秒预算，以及图像适配、平滑、渲染参数。面板可查看和修改提示词与运行限制，并按场景保存。原始绘图协议、整体／局部绘图操作、拓扑校验、图像适配、预览渲染和 `generic-dp-v1` 平滑算法已复制到插件自身，来源记录见 `python/provenance.json`。

模型输出只按声明式 JSON 解释，不作为程序执行。无效绘图会反馈给模型修订并保留上一有效结果；网络或本地处理服务异常停止本次运行，不自动重新提交模型请求。未绘图不能 finish。达到轮数限制时保留最后有效结果，明确标注尚未获模型确认。停止与超时会中止后续处理，不声称撤销远端调用。

图像处理需要本机 Python 和 NumPy、OpenCV、Pillow、Pydantic。可以使用已安装这些依赖的系统 Python，或运行以下脚本在插件自身创建独立环境（不使用 Map2Area 的环境）：

```powershell
powershell -ExecutionPolicy Bypass -File src/modules/partition-agent/python/setup.ps1
```

运行时优先使用插件 `python/.venv`，否则使用系统 `python`。也可通过 `LAYOUT_PARTITION_PYTHON` 指定解释器路径。图像进程由 3D-Layout 自动启动和结束，不需要手动启动额外服务。分区模型通过现有多协议客户端调用，密钥不会传给图像处理进程。

## 执行与权限

总 Agent 通过 `agent_dispatch` 一次派发多个分区任务，SubAgent 使用独立模型会话和全新历史，同时编辑同一场景。依赖任务由总 Agent 分批派发。总 Agent 保留全局编辑能力，提示词要求优先委派给分区。

每个对象的 `regionId` 标签存储在本插件的 `partition.owners` 侧表中，与对象 ID 绑定，不要求修改主体 SceneAsset 格式。`scene.get_state` 返回标签，面板提供对象归属列表。新建对象按世界 XZ 锚点归属；共享边界、重叠区域或分区外的对象标记 `__global__`，由总 Agent 协调。重新分区重建归属表。已有分区重新加载时保留已标注归属，补齐新增对象。

所有写工具通过本插件的 `scopedEdit`，逐对象检查归属；新建与移动同时检查目标锚点。材质、地形、散布和批量工具均经过同一入口。SubAgent 无法修改归属侧表。总 Agent 跨区移动对象后更新其归属。

权限允许的修改立即生效并记入宿主编辑历史，没有提案、人工接受、结果验收、冲突检查或统一提交队列。批量工具中后续操作被权限拒绝时，之前已应用的修改保留。各区模型调用和编辑流程并行，JavaScript 同步的单次编辑自然按到达顺序执行，不持有长事务。

归属以对象锚点为准，不保证整个模型包围盒留在分区内。地形等大对象也按对象归属控制，无法让多个分区分别修改同一地形对象的不同部分；这类跨区工作应交由总 Agent 处理。

并行视觉点选必须使用自己独立相机截图返回的 `screenshotId`，防止引用其他 Agent 的最近截图。Python 通过已有的本地隔离执行服务运行，其结果引用按各自上下文隔离；Docker 不可用时工具返回执行错误。

## 保存与生命周期

总 Agent 的完整工具对话、用户可见对话、分区设置、分区与对象标签保存在：

`scenes/<sceneId>/partition-agent/session.json`

浏览器缓存即时保存同一会话；磁盘保存异步合并同场景的连续更新。合法场景编辑也异步自动保存到该场景原有 `scene.json`。这些保存发生在修改生效之后，不控制提交。保存失败会在面板明确显示。原始／平滑边界、两种预览、绘图轮次与平滑报告随分区保存，预览使用本地图片数据，关闭软件后仍可查看。

浏览器缓存只保存精简镜像：截图图片与超过 250 KB 的预览图不写入 localStorage（刷新后由磁盘 `session.json` 恢复原图），镜像超出 800 KB 预算时先丢弃最旧的工具轮次，仍超配额时清理本插件其它场景的遗留镜像并退化为最小镜像。只有全部降级都写不进去，面板才提示“浏览器缓存未更新”，磁盘保存与场景恢复不受影响；`session.json` 不受这些裁剪影响，仍是权威副本。

切换场景、关闭插件或停止时中止后续工具调用，已应用修改保留。旧任务即使收到迟到响应，也无法继续编辑新场景。清除上下文会中止任务、更换总 Agent 会话 ID、清除聊天及工具历史，保留分区、对象标签和场景修改。刷新或重开软件后恢复对话与分区，未完成任务不会自动重新发起。

截图历史仅保留最近批次，大型历史结果缩减后仍可重新查询；文本历史没有自动模型摘要，长会话达到模型上下文上限时可清除上下文继续。

服务端接口由独立 Vite 插件提供，开发及预览均可使用。纯静态部署需要提供相同的本地图像处理和保存接口。旧版分区几何与归属数据可继续使用，恢复时去除旧远端预览地址；重新分区即可生成完全本地的预览。

## 验证

在 `src` 下运行：

```powershell
npm run test:partition-agent
npm run build
```

测试覆盖并行调度、上下文重建、立即编辑、批量越权、位置约束、取消、清空后迟到结果隔离、Python 引用隔离、分区坐标转换、原工作流配置、本地绘图—看图—修订—平滑完整链路及真实 HTTP 会话落盘与恢复；浏览器镜像另覆盖截图剔除、预览裁剪、配额降级与遗留缓存清理。模型调用使用模拟响应，图像与几何处理使用插件自己的真实 Python 实现，不调用付费模型或 Map2Area 服务。
